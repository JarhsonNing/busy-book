# 图书经营系统重整评估

评估日期：2026-10-26。依据当前工作区代码和本地文档，包括尚未提交的学校目录、采集适配器相关代码。本次是产品与架构评估，没有运行桌面端、外部平台联调或生产数据迁移，代码存在不代表功能已经通过真实业务验收。

## 1. 已确认的目标与边界

- 产品定位：围绕学校用书需求，完成图书建档、货源准备、图片整理、渠道销售、订单代发的经营系统。
- 首期以无库存代发为主，保留现有库存字段，兼容未来自有库存；首期不展开仓库、盘点等完整库存流程。
- 主动采集优先级：学校与专业的官方用书目录 → 识别具体图书 → 找货源与图片。
- 保留闲管家、淘宝、孔夫子现有对接能力和登录窗口。业务层与页面可以重组，通过适配层衔接既有接口。
- 现有图书、图片、货源、电子资源、渠道关联、订单、采购和历史记录应能迁移、查询和追溯。
- 一级导航收敛为“闲管家、图书、采集、设置”。暂不设置工作台，启动进入闲管家的订单页。
- 学校维度与图书维度置于同一“图书”模块内；货源与图片置于单本图书的二级详情，不设置独立管理入口。

## 2. 结论

建议重整业务模型、信息架构和业务页面，继续使用现有 Vue、Rust/Tauri、SQLite 技术基础。

主要问题是目录、书库、货源、图片和销售之间没有形成统一工作流程。学校维度和图书维度应当是同一套业务数据的两个入口，不能再形成需要手工来回同步的两套库。

保留采集原始材料和解析快照是必要的；需要消除的是把“离线目录导入和数据库重建”作为普通用户的日常操作。

## 3. 当前实现的具体问题

| 问题 | 代码依据 | 业务影响 |
| --- | --- | --- |
| 学校入口分裂 | App.vue 同时包含“学校书单”“考研目录”“图书中心” | 查看目录、确认书目、整理经营资料需要跨入口跳转 |
| 目录与经营书库分离 | catalog_browser.rs 读取独立 catalog.db，再用 school_requirements 中的 candidate.id 关联 books | 目录中能看到书，不代表书库中可以直接经营 |
| 流程暴露内部步骤 | KaoyanCatalog.vue 提示先导入 catalog.json，再去学校书单确认 | 使用者必须理解文件、导入和关联关系 |
| 版本聚合与销售对象不同 | build-catalog.mjs 的 bookKey 采用书名与出版社或作者，另聚合 editions、years、volumes | 聚合教材不能直接当作可采购的具体版本；现有人工确认机制应保留其业务意义 |
| 图书列表缺少需求上下文 | BookTable.vue 展示书名、ISBN、成本、售价、图片和状态，未直接展示学校、专业 | 看书时无法快速判断对应学校与专业，也难以按需求准备销售 |
| 图片准备情况不清晰 | images 表直接关联 book_id；编辑、导入、删除主要在图书详情内 | 保留按书管理，但需补充用途、处理与核验状态，在图书列表暴露缺图情况 |
| 主动采集尚未产品化 | catalog_collect.rs 依赖源码目录和系统 node，收集进程输出后才返回请求结果 | 缺少持久任务、断点恢复、取消和运行进度；当前实现明确不适用于打包后的安装环境 |
| 状态混合 | books.status 包含待整理、待发布、已上架、已售出，同时另外计算货源、资源和渠道状态 | 多货源、多店铺、多次销售时，单个图书状态无法准确描述经营情况 |
| 数据量扩大后需要调整查询 | commerce/books 逐书补充关联信息；App.vue 每 8 秒拉取书库并在前端过滤 | 学校与图书数量增加后，应改为后端筛选、分页、聚合及按需刷新 |

当前可复用基础包括：多货源与主选货源、书目确认、资源版本、渠道绑定、订单履约、采购尝试、事件记录、图片编辑、发布任务与结果核查。应重组其使用流程，再逐项验证。

## 4. 核心业务关系

### 学校用书关系

学校 → 招生年份或学年 → 学院与专业 → 科目与考试阶段 → 用书要求。

学校详情默认先展示专业，年份作为明确筛选项，学院作为分组项。避免让用户反复钻入过多层级；具体用书表中展示初试、复试等阶段。

每条用书要求独立保存学校、专业、年份、科目、原始书目、原文地址、采集时间和版本要求。用书要求可以先存在，不强制立即绑定具体图书。

### 图书关系

“书名分组”用于搜索与归类；“具体版本”是经营主对象，承接 ISBN、作者、出版社、版次和册次。

一个具体版本可以被多个学校和专业使用；一条用书要求如明确允许多个版本，应关联多个已确认版本，并记录适用理由。不能把“同名书”自动视为同一商品。

ISBN 是重要匹配依据，仍需结合版次、册次和原文核对。没有 ISBN 的记录也可以进入待完善区，不能因此丢弃需求。

### 经营关系

具体版本 → 多个货源及其可购买规格。

具体版本 → 图片素材及发布图片组合。

具体版本 → 不同店铺的销售商品 → 销售订单明细 → 采购记录 → 物流与售后。

图书档案不等于平台商品。同一书在不同店铺可以有不同标题、售价、图片和商品 ID。

## 5. 页面与导航

一级导航仅保留四个入口。采用紧凑侧边导航，图书、采集和设置不再拆分为更多一级模块。跨模块打开图书时保留原筛选、页码和学校上下文；轻量编辑用抽屉，完整图书资料用详情页。

| 入口 | 主要用途 | 关键内容 |
| --- | --- | --- |
| 闲管家（默认） | 处理当前销售业务 | 订单处理、商品与渠道库存、发布记录、店铺切换 |
| 图书 | 查看和准备自己的图书 | 图书与学校两个视角；单本图书的资料、货源、图片和销售关联 |
| 采集 | 发起并跟踪采集 | 学校官方来源、执行进度、结果审核、失败重试和历史 |
| 设置 | 配置连接与经营规则 | 现有平台对接、图片托管、定价规则和应用设置 |

不设置工作台、货源中心、图片中心、独立销售中心或独立统计入口。订单问题在订单页处理，图书缺项在图书列表筛选，采集异常在采集页处理。统计只在相关页面提供有业务依据的小计。

### 闲管家：启动后的默认页面

默认进入订单页，优先显示待发货订单；仍可切换全部订单、售后和其他平台状态。缺少配置时在当前页面显示连接说明和“前往设置”操作；已配置但请求失败时保留页面并提供重试与错误原因。

闲管家内保留两个主要二级页签：“订单”“商品与库存”。店铺切换放在模块头部，展示当前查询范围与授权状态；店铺详情按需展开。发布记录从商品页进入，不再作为一级导航。

- 订单：提供平台支持范围内的店铺、时间、状态筛选与订单号查询。列表显示订单、商品、数量、实付、销售状态、采购进度和物流；采购进度属于本地经营记录，与平台销售状态分开显示。
- 订单详情：同页完成关联图书、查看主备货源、登记采购、录入物流、回传发货及售后记录。需要改图书资料时跳转图书详情，返回后恢复订单上下文，不另外跳转到“订单履约”模块。
- 商品与库存：查看在售、下架和异常商品，展示渠道商品 ID、关联图书、售价、渠道可售数量和更新时间；在现有接口支持范围内提供编辑、库存调整、上下架及发布本地图书。
- 发布记录：作为商品页的子视图，查看发布中、成功、失败和结果未知，支持核查与继续处理；不以请求已受理代替上架成功。
- 库存：此处的主要库存为闲管家渠道可售数量。本地自有库存作为关联图书的辅助信息，不混为一个数字；无库存代发不根据本地零库存自动下架。
- 现有多规格价格与库存编辑限制继续准确展示，不因新设计虚构接口支持能力。列表内本地筛选与远端检索范围明确区分，不把当前页筛选称为全店搜索。

接入设置统一迁到“设置”，闲管家模块仅保留连接状态及前往设置的入口。

### 图书：同一模块的两个视角

图书模块提供“按图书”“按学校”切换，默认进入当前管理的图书列表。学校书单与考研目录合并到“按学校”，不再要求用户在两个模块之间导入和确认。

两个视角使用同一图书详情。采集得到但尚未确认版本的用书记录显示“待匹配”，可就地匹配或完善；已确认的书直接打开详情。普通非学校用书也能手动加入与管理。

### 学校维度

1. 学校列表：学校名称、已有年份、专业数、用书数、最近采集时间、待确认数。
2. 点击学校：学校概况与专业列表；专业可按学院分组，可搜索专业名称或代码。
3. 点击专业：展示所选年份的用书表，按科目、阶段分组。
4. 用书表：官方原文、已匹配图书版本、货源准备情况、图片准备情况、已上架店铺和待办。
5. 当前范围可批量发起“更新官方目录”“匹配图书”“查找货源”“补充图片”“准备销售草稿”。

没有采集结果、学校未公布书目和明确不指定参考书，应显示不同状态。历史书单不能自动冒充新年份书单。

### 图书维度

列表默认展示：封面、书名与具体版本、ISBN、适用学校数与专业数、主选货源含运费成本、参考售价、图片准备情况、渠道商品数和待办。

学校与专业可展开查看，点击可回到对应专业用书表。筛选支持学校、专业、年份、版本确认、货源状态、图片状态和渠道状态；支持可配置列与批量操作。

### 单本图书的二级详情

完整详情保留“资料、货源、图片、销售记录”四个页签。页首始终显示封面、书名、ISBN、版本和当前缺项；从哪个视角进入都打开同一详情。

- 资料：基本字段、适用学校与专业、官方用书原文与版本核对、本地库存兼容字段。已有电子资源以可展开区块保留，不强制每本实体书配备电子资源。
- 货源：淘宝采集候选、规格与版本核验、价格与运费、主选和备用、代发情况及报价历史；在本页发起找货源并查看关联任务进度。
- 图片：找图、本地导入、用途归类、原图与处理图、编辑、核验、主图和排序；操作沿用现有编辑器，在本页完成日常管理。
- 销售记录：展示店铺商品、售价、可售数量、发布状态与关联订单；发布本书进入既有发布流程，处理订单则进入闲管家对应订单。

图书列表支持“缺货源”“缺图片”“待确认版本”等快捷筛选，并可对选中图书批量发起补全任务。批量执行进度统一汇总到采集页，不另建货源或图片管理页面。

### 采集：进度和结果

默认展示运行中与近期任务，提供“新建采集”。新任务以学校、年份和官方来源为主要输入；图书详情发起的货源、图片任务也在这里显示。

每项任务显示学校或图书范围、当前阶段、已处理与总量、成功与失败数，以及等待人工操作的原因。任务详情提供失败项重试、暂停、继续、取消和结果审核。总量尚未确定时显示已处理数量与当前阶段，不展示虚假的百分比。

结果可直接进入对应学校、专业或图书详情。采集源与解析方式放在新建任务或任务详情的按需展开设置中，普通操作不要求上传代码或操作 catalog.db。

### 设置

集中管理闲管家应用凭据与连接测试、店铺授权状态说明、图片托管、定价与文案默认值，以及已有应用设置。设置保存后，相关模块直接使用更新的配置。

## 6. 主动采集的完整流程

主流程：选择学校和年份 → 获取官方目录 → 解析专业与用书 → 匹配已有版本 → 审核变化 → 查找缺少的货源与图片 → 准备销售。

### 第一层：学校官方目录

- 每个学校保存官方入口、已支持的解析方式、年份及最近成功时间。
- 采集对象包括官方目录页、学院公告、PDF 和表格附件；不同学校逐步增加适配，不能承诺一个通用解析器覆盖所有学校。
- 新学校先登记官方来源，再测试采集；未知结构进入待适配状态。自动发现入口是增强能力，不能当作必然成功的前置条件。
- 保存原始文件或页面快照、解析结果、来源和错误，支持追溯。
- 更新生成“新增、内容变化、未再出现”的差异；未再出现不直接删除，需区分完整采集和部分失败。
- 官方书目变化只更新需求证据和待审核状态，不自动覆盖已核实版本、采购记录或已发布商品。

### 第二层：图书匹配

- 优先检查 ISBN、作者、出版社、版次和册次；同名只能产生候选。
- 明确匹配可批量确认；存在多版本、缺字段或冲突时提供并排对照。
- 保存匹配依据与确认结果，后续重复采集复用已确认关系，内容变化则重新核查。

### 第三层：货源与图片补全

- 针对当前专业、学校或勾选图书批量建立查找任务，优先处理缺主选货源、缺可用图片的书。
- 继续调用淘宝、孔夫子已有窗口与采集能力；搜索结果批量读取能力需要单独实现和验证，已有“抓取当前商品页”不等于已有自动搜索采集。
- 支持通过现有登录窗口接管需要登录、验证或手工选择的步骤，并保存任务上下文。
- 候选货源先比对版本、价格、运费和规格，再确认关联。图片先归类和核验，再用于发布。
- 目录采集、货源采集、图片采集是不同任务类型，复用同一个任务中心。

### 任务机制

首期支持手动发起持久批量任务，记录任务范围、来源、解析器版本、进度和逐项结果。提供排队、运行、等待人工处理、完成、部分失败、失败、已取消状态，以及暂停、继续、取消和失败项重试。

持久保存任务与检查点，应用重启后恢复待运行任务，避免重复入库。解析、匹配与确认分开计数，不能把“请求完成”直接显示为“全部入库完成”。

随后增加在应用运行期间检查到期来源、按变化更新的功能。应用关闭期间继续采集需要额外常驻服务，桌面端首期不默认承诺这一能力。

安装版必须从应用数据目录加载任务与适配配置，明确提供采集运行环境；不能继续依赖开发机器的源码路径和 Node 安装。

## 7. 货源、图片与代发

### 图书详情内的货源管理

货源包含平台、商品链接与 ID、店铺、可购买规格、所关联图书版本、品相、价格、运费、代发情况、核验时间和状态。商品包含多个规格时，应按具体可买规格记录报价。

每个图书版本有主选与备用货源。保留报价历史，过期报价或失效链接进入待办。替换主选货源不修改已经形成的采购快照。

列表提供含运费成本和参考毛利；缺少成本或费用时显示“待核算”。下单前仍需重新核对版本、数量、收件信息和实际金额。

### 图书详情内的图片管理

素材记录来源、内容摘要、用途、对应具体版本、处理状态和处理历史。区分封面、目录、版权页、详情和实物品相。

批量找图、导入、去重、归类、处理、核验和排序。复用现有编辑器，保存原图与处理结果；同图用于多个商品时通过引用管理，避免删除一个关联就删除仍被使用的文件。

共用封面可以复用，反映某本实物品相的图片不能自动套用到其他货源。销售商品选择自己的发布图片组合，保留发布时的图片快照。

### 代发流程

销售订单同步 → 匹配商品与图书版本 → 核查主选货源 → 生成采购待办 → 人工付款并登记采购 → 登记物流 → 回传销售渠道 → 售后与核算。

初期继续采用现有淘宝窗口人工下单，不把“自动采购付款”列为默认能力。订单明细允许未来扩展多书、多货源和拆单，首期优先完成单书代发闭环。

保留 books.stock 的既有值与接口兼容；另行区分履约方式和渠道可售数量。库存为零不代表代发商品不可售，库存大于零也不自动证明存在可用货源。

已有电子资源、交付证据与双规格草稿继续可查。当前代码对混合发布仍有限制，界面重整不能把未验证的平台能力显示为可用。

## 8. 数据与技术调整

- 保留现有具体版本图书 ID，按需增加书名分组，不以重建 ID 的方式统一数据。
- 学校、专业、年份与科目使用结构化关系；保留原始名称和官方来源。招生年份、书籍出版年份分别存储。
- 用书要求、原始采集快照、版本匹配分别记录；多个页面使用同一业务查询层。
- 采集原文和调试材料可以独立归档，界面上的学校和图书关系由统一经营数据管理。
- 货源、渠道、订单和图片各自管理状态，图书概览根据实际准备情况汇总待办，不以一个状态字段替代全部业务。
- 增加任务持久表、逐项任务结果、采集来源和采集快照；将暂停和取消落实到执行器。
- 将图书与学校的搜索、筛选、分页和汇总放到后端，避免全库轮询与逐书查询关联数据。
- 当前架构继续采用本地单应用和 SQLite；首期没有依据引入微服务或多用户协作系统。

## 9. 分阶段实施与验收

### 第一阶段：收敛导航与统一两个主视角

先收敛到四个一级入口，默认打开闲管家订单页，统一设置入口；完成现有数据库一致性备份、迁移映射、学校与专业关系、用书要求、版本匹配和图书模块内的两个视角。先做一个学校的端到端样例，再迁移全部数据。

验收：启动进入闲管家，订单、商品与库存可操作；从学校进入专业能看到对应书目及经营资料；从任意图书可反查学校、专业、年份和科目；两个视角打开同一详情；重复导入不重复建书；多版次不会误归并；保留历史 ID 与关联。

### 第二阶段：学校主动采集与任务中心

复用现有学校适配器，补持久任务、进度、失败重试、结果审核、差异更新和安装版运行环境。

验收：重启后可恢复未完成任务；重复执行不重复建档；部分采集失败不误删历史；官方目录变化能定位到原文；安装后无需源码目录即可运行。

### 第三阶段：货源与图片批量准备

重做图书详情中的货源与图片页面，贯通从专业用书表或图书列表发起的查找、候选确认和批量处理；任务在采集页汇总。

验收：主备货源可切换并追溯报价；候选版本冲突可识别；图片处理不丢原图；共用图片删除安全；每个任务可定位成功和失败项。

### 第四阶段：销售、代发与经营核算

将现有发布、店铺商品、订单、采购、物流与核算整合在闲管家模块，完成与图书详情的联动。

验收：一笔真实测试订单能关联销售商品、图书版本、采购货源和物流；未知发布或发货结果不会盲目重试；缺失成本不计为零；平台对接通过回归验证。

每阶段都接通现有平台能力并完成回归，不等到最后才检查接口兼容。统计围绕真实订单和成本建立，不优先制作缺乏数据依据的总览图表。

## 10. 实施前仍需明确的事项

- 首批目标学校、年份与官方入口，用于定义第一阶段样例和第二阶段采集覆盖范围。
- 同一专业是否需要出售整套书；若需要，应增加套装与组成明细，不能把套装当成一个普通 ISBN。
- 图片处理是否只需现有能力，还是还需要统一商品模板。可在图书详情的图片页设计时确认，不影响先统一学校与图书关系。
- 需要用实际书库与订单备份验证迁移规模和异常数据；本次未读取用户运行中的生产数据库。

上述待定事项不影响总体方向：以学校用书需求启动经营，以具体图书版本贯穿货源、图片、商品和代发。
