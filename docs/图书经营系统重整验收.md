# 图书经营系统重整验收

日期：2026-10-26

## 订单发货与内部采购关联（2026-10-28）

入口：闲管家订单列表 → 发货，或订单详情 → 采购与物流。发货弹窗分为“填写物流”和“淘宝采购”，没有增加一级入口。前者不依赖采购单或已建货源，填写快递公司、单号并确认即可；后者允许手动打开淘宝购买，回填淘宝订单号、采购状态、可选实付金额、店铺、规格和内部备注。收件信息按需从销售订单读取，仅保留在当前窗口内存中，不自动发送给淘宝。

采购订单号、货源和备注仅存储在本地 purchase_attempts 及内部操作记录。关联采购与更新供应商发货状态都不会调用闲鱼写接口，也不会修改闲鱼商品、订单备注或给买家发送消息。只有用户在弹窗中勾选核对并点击“确认发货”，才调用既有闲管家发货接口；出站字段固定为销售订单号、快递编码、快递名称和物流单号四项。

内部流程为已下单待物流 → 待回传物流 → 闲鱼发货结果核查。采购物流录入后，销售订单仍为待发货；远端成功受理后再查询订单确认。超时、进程中断等未知发货结果保留核查状态，阻止盲目重发及改写采购或单号；发货执行期间也不允许并发改写物流。已识别的电子订单不能走实体发货。未映射的订单须由操作人明确确认实物商品。进行中售后、未付款、取消以及数量未知的订单不能新发货。

单笔销售订单保留一条有效采购关联，并保留取消/更换历史。同一采购单不重复关联另一销售订单；已下单的采购编号不可直接覆盖，需核实取消后重新关联。没有填写的采购成本仍为未知值，不按零核算。旧采购记录兼容，字段扩展使用现有 JSON，不清理历史数据。

验证：58 项 Rust 库测试通过，前端生产构建、API 服务及桌面程序构建通过。新增测试覆盖无采购直接填物流、未匹配订单手动确认、电子订单拒绝、重复采购关联、重启恢复、未知成本、取消清理旧物流和并发操作互斥。HTTP 模拟平台测试明确断言：内部保存不会触发平台调用；实际发货请求只有四个允许字段，采购单号、采购金额、供货店和内部备注不会进入任何远端请求。

使用 scripts/shipment-review.mjs 的模拟订单进行浏览器操作验收：从订单列表打开发货弹窗，保存物流、确认模拟发货并核查、保存淘宝采购、关闭重开恢复关联、供应商已发货而闲鱼仍待发货、按需读取收件信息、焦点循环及 Escape 关闭。1080×700 和 1360×880 下默认表单没有内部滚动或横向溢出；可选商品与备注按需展开。模拟“去淘宝购买”只记录本地动作，没有打开实际淘宝或提交采购。截图为 shipment-taobao-minimum.png、shipment-taobao-desktop.png、shipment-manual-minimum.png。

当前淘宝采购状态及单号由用户手动更新，没有实现淘宝已购订单自动同步。未使用真实销售订单执行平台发货；真实账号验收不能由上述模拟测试替代。

## 一键找最低价（2026-10-27）

入口：图书详情 → 货源 → 一键找最低价。优先使用 ISBN，否则组合书名、作者、版次；向淘宝请求价格升序检索。按用户提供的 2026-10-27 HTML 修正为滚动采集，不再按 44 条偏移量构造分页 URL。追加和虚拟列表中的商品均累计去重，最多 3 个保存批次（每批最多 60 个候选）；到达当前加载边界后结束。只有真实可用的主结果“下一页”按钮存在时才点击，排除顶部轮播分页；无响应时暂停，不重复点击。使用已有内嵌浏览器登录会话，不另存账号密码。

价格按 `priceInt` 与 `priceFloat` 分别读取，避免整数价后接付款人数而误解析；使用 `shopNameText` 读取店铺，并保留“补贴后”等 `priceDesc` 标签。比较同时展示本次候选与已有淘宝货源。展示价仅供筛选；只有已确认版本规格、品相与本书一致、支持代发，且采购价和运费均明确的可用货源，才计入“最低已核验含运费价”。未填写图书品相时，不生成已核验最低价。核验时间可见，候选可直接进入编辑弹窗。结果仅代表采集范围和已有报价，不承诺全网最低，也不推断优惠券、其他 SKU 或未知运费。

任务按图书持久保存，带请求 ID，支持停止、继续和重启后继续；过期回传、乱序批次、停止或暂停后的新批次不会写入。恢复时跳过已保存的商品，继续滚动。沿用旧任务 `pagesDone` 的存储以保留历史，接口另外提供 `batchesDone`，页面仅显示候选数量和滚动采集。复用一个淘宝窗口，切换另一图书比价时暂停原任务。登录、验证遮罩、页面未就绪或超时会暂停并保留已采集结果。检索结果不会覆盖已核验报价或自动新建图书。

旧书库首次加入比价表前执行备份；新增 `price_searches` 表保存采集快照和进度。使用整数分比较采购价加运费，未知值不按零处理。

验证：55 项 Rust 库测试、17 项相关 Node 脚本测试、前端生产构建通过。隔离 HTTP 验收使用 `scripts/price-search-smoke.mjs`，覆盖滚动批次去重、当前加载结果结束、核价排序、品相/运费/代发缺失排除、重复回调、取消、切换图书暂停、进程重启与继续。脚本测试覆盖追加与虚拟列表、首 60 条之后的新结果、真实分页按钮与无响应暂停、验证弹窗出现前结果保存，以及空页面不误完成。

用户粘贴的商品 HTML 已精简为 `scripts/fixtures/taobao-cards.html`，移除脚本、图片、跟踪参数及账号界面，并替换商品 ID；动态插入的嵌套店铺链接改为 span，以免 HTML 重解析破坏卡片嵌套。运行 `node scripts/taobao-dom-fixture.mjs` 后在本地浏览器验证三张卡片的 52.48、19、22.48 元、补贴标签、店铺、结果容器滚动和主结果分页辨别通过。截图 `taobao-scroll-dom.png`。

此前页面验证了一键创建、排序切换、直接打开核验弹窗、保存后最低价自动更新、停止保留货源；1360×880 和 1080×700 无横向溢出，编辑弹窗仍无需滚动。截图 `lowest-price-desktop.png` 与 `lowest-price-minimum.png` 为初版分页文案的模拟数据，仅作为当时布局记录。

## 补充：平台登录状态

淘宝、孔夫子窗口显式使用应用固定的本地 WebView2 数据目录并关闭无痕模式，沿用 Tauri 原先的默认目录以兼容已有 Cookie 和网站存储。普通关闭平台窗口改为隐藏，再次打开会显示并复用原会话；关闭主窗口会退出整个应用，隐藏窗口不导致应用常驻。

应用重启后复用原来的持久化登录数据。网站设置的会话期限、主动退出、异地登录或安全验证仍由网站决定，不能保证登录永久有效。应用不另行保存账号密码，也不把会话 Cookie 写进业务数据库或日志。

Rust 离线编译检查通过；真实账号的“关闭再打开窗口”和“退出应用后重新启动”登录保留需现场验收，不能用编译检查替代。

## 补充：淘宝货源查询

入口为图书详情的「货源 → 淘宝找货源」。按 ISBN 优先，否则组合书名、作者和版次搜索；搜索窗口携带本书 ID。内嵌浏览器等待结果加载，读取当前可见的淘宝/天猫商品卡片（单次最多 20 个），回传商品标题、店铺、展示价格和链接。缺失数据留空，不推断运费或规格。

候选直接进入当前图书，状态为待核验，未确认代发。返回页面触发刷新，也可点击「刷新货源」。商品详情保留「抓取本页」作为补充，点击商品链接时继续携带目标图书。重复采集不覆盖已核验信息；同一商品可为不同版本建立独立待核验记录，不转移原有关联，也不自动新建图书。

登录、验证及页面结构变化可能使卡片暂不可读取，窗口限时等待后提示手动重试或进入详情；不会宣称找到可用代发。真实淘宝登录会话中的现场验收尚未执行。Rust 库 52 项测试通过，新增淘宝注入脚本 3 项模拟测试通过，孔夫子注入脚本 2 项回归通过，前端生产构建通过。

隔离 API 验收：向同一本书重复提交模拟淘宝商品两次，未新建图书，只保留一条本书待核验货源；浏览器实际查看货源页并点击刷新通过，截图为 `taobao-source-fixture.png`，商品明确标注为模拟数据。

## 实现范围

- 一级导航为闲管家、图书、采集、设置；默认打开待发货订单。
- 闲管家重新组织订单、商品与库存、发布记录。订单详情汇集图书关联、采购、物流、核算与售后；经营统计折叠展示。
- 图书采用后端搜索、筛选、分页；图书与学校两个视角共用图书 ID 和详情。学校视角保留学院、专业、年份及原始用书依据，包括暂无用书记录的专业。
- 图书详情包含资料、货源、图片、销售记录。电子资源、渠道规格和混合规格配置收入详情；接口与网页发布统一从发布按钮进入。
- 图片支持上传、链接导入、主图、排序、删除、编辑和保存。货源支持本书管理及浏览器采集候选关联。
- 本地库存和渠道可售数量分开；本地库存为零不会触发代发商品自动下架。
- 采集任务写入 SQLite，返回任务 ID，支持进度、结果、暂停、继续、取消、失败重试，以及进程重启恢复。
- 设置集中管理平台连接、图片托管、定价、发布默认值与应用配置。

## 采集边界

学校目录采集接入现有华东师大适配器及通用官方文章适配器。通用适配器需要提供官方文章地址；本次没有实现全互联网自动发现所有学校官网。

目录采集后，专业用书与原始证据进入学校视角。版本由经营者确认关联或新建，保留 ISBN、作者、版次、册次等区别。重复采集复用记录，已有明确关联在相同原始证据下保留；原始用书证据变更后重新确认。

批量找货源、补图片和准备发布进入持久任务列表。货源与图片使用现有浏览器辅助采集并验证结果；不会把等待人工处理的项目显示为自动完成。未验证的混合规格和电子交付执行能力继续受原有能力检查限制。

## 数据与运行环境

采用增量建表和字段兼容，不自动清除历史数据。首次给已有书库建立新的业务任务结构时，先生成 `shelf-before-commerce-时间戳.db` 备份。既有图书 ID、订单关联、原始采集依据继续使用。

采集产物按尝试写入独立目录，完整产出后更新目录索引；暂停或取消结束子进程。API 异常退出后，采集子进程通过父进程监测退出，运行中任务在重启时重新排队，暂停任务维持暂停。

构建前打包采集脚本、Node 运行时与许可文件；桌面运行时从资源目录定位采集器，使用应用数据目录保存采集数据。可以通过 `TAOSHU_COLLECTOR` 指定运行环境，开发环境仍可使用仓库脚本。
