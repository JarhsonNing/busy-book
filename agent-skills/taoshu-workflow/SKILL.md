# 图书经营流程

完成“获取书籍信息并入库 → 搜索图片 → 搜索并选择货源 → 生成经营草稿 → 闲鱼上架 → 核查结果”。用户可指定起点，未指定则检查现状后从首个缺项开始。开始于中间环节不表示重做前序工作，也不表示忽略发布前提。

## 接续与工具

- 先连接应用的 `taoshu` MCP，调用 `taoshu_context` 并读取实际工具定义；用 `taoshu_search_books` 定位已有图书。存在多个版本时展示候选供选择，不让用户重复输入已能读取的信息。
- 从应用图书详情核对现有资料、图片、主选货源和销售记录。用户已给出 ISBN、bookId、图书链接或选中图书时直接使用；只有无法唯一定位时才询问。
- MCP 提供书目查询、四类导入，以及 `taoshu_generate_draft` 的受限草稿生成和任务查询；不提供读取完整经营详情、设主选货源或发布商品的工具。后几项使用已接入的应用界面操作工具；仅当实际发现相应能力时才调用。不能用导入令牌调用管理接口、索取平台密钥或直接改数据库来绕过限制。缺少界面工具时，向用户交付已准备的候选、草稿及对应页面的操作步骤，明确需要用户完成的动作及其余待办，不声称已写入页面或整条流程已结束。
- 任一阶段满足条件就复用；前提缺失时只补必要缺项，再回到用户指定阶段。先在当前任务记录 bookId、起点和各阶段状态，后续记录图片/货源编号、确认范围、发布任务或商品编号。恢复时重新读取实际结果，不仅依赖旧对话。

| 用户指定起点 | 继续方式 |
| --- | --- |
| 获取资料并入库 | 检索、匹配版本并入库，然后依次补图片、找货源和发布。 |
| 搜索图片 | 复用现有图书，补齐适配图片，再处理货源和发布。 |
| 搜索货源 | 复用图书和有效图片，检索、比较并等待货源确认，再准备发布。 |
| 闲鱼上架 | 读取现有图书、图片和已确认货源；缺项才补，发布前展示具体草稿供确认。 |

“待确认”和“结果未知”均为尚未完成的阶段。用户只要求做到某一阶段、暂停或取消时，尊重其范围；不要继续上架。

## 获取资料与图片

1. 缺 ISBN 时先用 `taoshu_lookup_isbn` 按 `query` 查询豆瓣候选，必要时用候选的数字 `subjectId` 查询指定详情，核对作者、出版社、版次和册次；不要把第一条同名书当成唯一匹配。查询不会自动写库，受限或详情缺 ISBN 时保留准确状态，按返回的等待时间停止重试，不换通道绕过验证。其他书目信息使用当前可用且允许访问的搜索、网站或浏览器工具检索，优先出版社及学校官方目录。学校引用保留学校、年份、专业和原始用书依据。将已知条件带入检索，不要求用户自行拼搜索词。
2. 核对版本后单本使用 `taoshu_import_book`，多本优先用 `taoshu_import_books` 分批入库（每批至多 200 条，字段同单本）；逐条检查成功、复用或失败结果，保留失败原因并只补必要资料。必要时调用 `taoshu_import_school_book`。每条保留真实 `sourceUrl` 与稳定 `source`、`externalId`；同一请求重试沿用原参数。同一外部编号内容发生变化时先核对，再使用明确的修订编号；不通过反复换编号掩盖失败或制造重复记录。
3. 搜索对应版本的封面和实物图片，核对版次、册次及封面文字，使用 `taoshu_import_image` 上传真实 PNG/JPEG/WebP 字节的 Base64（最多 10MB），保留来源。也可使用应用“图书 → 详情 → 图片”的现有导入、上传、编辑和“设主图”功能。保留已可用图片及排序，不为了补图覆盖已有人工处理结果，不以占位图冒充完成。
4. 发现登录、验证码、访问阻止或未加载到真实内容时，保留当前进度并明确所需支持；不要将搜索摘要、猜测的 ISBN、模型生成信息或未知运费当成核验事实，也不要通过更换访问通道绕过已经出现的访问限制。

## 货源选择：确认点一

- 在相同 ISBN、版次、册次和可接受品相范围内搜索，优先复用已有可用货源。可使用应用“货源 → 一键找最低价 / 淘宝找货源”，或当前允许的检索工具；将新候选通过 `taoshu_import_source` 保存为待核验候选。
- 比较实际规格价格、运费、含运费总价、店铺、品相、代发和发货条件，未知值明确标记。默认无库存代发，不因本地库存为零淘汰图书；未确认代发条件的货源不能宣称符合代发要求。只把已核验且满足条件的候选称为本次范围内最低价，不能把最低展示价称为全网最低价。
- 提供简短候选表，包含编号、链接、版本/规格、价格与运费、代发及待核验项，并给出推荐理由。让用户选择编号或确认具体候选，不要求重新抄链接和金额。搜索、保存候选不需要额外确认；**设置或更换主选货源前必须得到用户对具体候选的确认**。
- 确认后在应用“图书 → 详情 → 货源 → 编辑”保存所选记录、实际已核验条件和主选货源。用户选择不等于真实性证明；无法核验的项目继续标为待核验。读取保存结果后再继续。没有可用候选时停留在本阶段，不用零成本或未知货源强行发布。
- 默认实体代发流程中，可用于发布的主选货源必须核对 ISBN/版次/册次及实际规格、品相，具备有效采购价和明确运费，当前可购买且支持代发，并保存图书关联、规格及核验记录为“可用”。上述任一项仍未知、不可用或与图书不符时，停留“待核验”，不因用户选中就标为可发布，也不能绕过应用预检。发货时效等其他待核验项如影响发布承诺，先补证据或删除无依据承诺。

## 闲鱼上架：确认点二

用户要求 AI 完善时，先调用 `taoshu_generate_draft({action:"start",bookIds:[...],task:"complete"})`，用返回的任务编号调用同一工具 `{action:"status",jobId:...}` 查询。任务也在应用采集页显示，批量最多 100 本；`pricing` 只分析定价，`copy` 只生成上架文案，`text` 生成自定义文本。按需传本次 `prompt`，否则使用设置里已保存的模板；使用已配置的模型，不擅自改成付费模型。逐本检查 `result.items`：只有 `done` 才表示草稿已写入，`failed` 继续保留原因；暂停、取消或模型受限不等于完成。

参考成本固定为淘宝有效商品价按不同价位去重后的第二低价，**不含运费**；不足两个价位时待补充，不用最低价或零元代替。成本由程序计算，模型不能覆盖该规则。运费单列；搜索报价仍须核验规格和成交条件，参考价不等于已成交采购成本。AI 结果自动写入本地草稿，但不设置主选货源、不修改远端商品、不提交发布。出现人工并发修改、过期依据或模型额度不足时，按返回原因处理，不盲目重试。

用户要求命令行生成时，优先使用图书“AI 完善 → 复制命令”提供的命令。接入包中的 `ai-generate.mjs` 支持 `--book 34,35 --task complete|pricing|copy|text --text`，可带 `--prompt`、`--provider opencode|qoder` 和 `--model`；MCP 的 `taoshu_generate_draft` 也接受 `provider` 与 `model`。未指定时沿用 AI 流程保存的执行器及其模型，任务创建后保持配置，不自行换用另一执行器或付费模型。通过同目录连接文件的受限 MCP 令牌调用，不需要管理令牌或数据库路径。

1. 用当前书目、有效图片、已确认货源及应用已有定价和发布默认值准备草稿。检查店铺、标题、ISBN/版本、描述、图片及主图顺序、品相、售价、运费、渠道可售数量和发布方式。保留自有库存字段；渠道数量与本地库存分别处理，不将代发库存直接写回本地库存。
2. 读取既有发布任务和商品关联。已在售且满足本次目标时核查并复用，避免重复创建；用户明确要求修改、重新发布或另一个店铺时按其具体范围处理。
3. 从图书详情“发布”进入“闲管家接口”或“闲鱼网页”，填写可读取的字段、展示草稿与关键金额，并检查预检结果。**真实创建商品或上架之前，必须得到用户对具体图书、店铺、草稿和执行方式的确认**。货源确认不是上架确认，“按流程继续”不是对尚未展示的发布草稿的确认。按钮叫“创建并测试图片”或“只创建”仍会创建真实商品，同样需要确认。
4. 用可选编号、现有选项或“确认上架 / 修改”接收决定。当前会话已有针对同一草稿、相同参数的明确授权时沿用，不重复询问；货源、成本、售价、店铺、版本、图片或发布方式发生实质变化时先更新草稿再确认。批量确认须列出每本对应内容，不能推定未列出的图书也获授权。
5. 用户确认后执行现有发布操作；遵守系统预检与混合规格等能力限制。拿不到准确的地区、分类或必填属性时提供有效选项供用户选，不猜值或用空值绕过验证。
6. 提交后记录返回的任务/商品编号，在“闲管家 → 商品与库存 → 发布记录”等现有视图核查远端商品、图片和在售状态。请求受理、仅创建草稿或网页打开均不等于已上架。超时、断线或结果未知时先查原任务及远端商品，不能盲目重新创建；只有明确未创建且确认范围仍有效时才重试。网页方式没有可验证结果时保留待核查。

## 完成与恢复

每本书最终给出简短结果：图书编号、图片、选定货源、发布任务/商品编号、远端状态；未完成项注明具体卡点与下一步。只有核实目标店铺的商品已在售、版本与图片正确时，才标记“已完成”。本 Skill 不包含采购支付、订单发货和售后；这些需要用户另行发起。
